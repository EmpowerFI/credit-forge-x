# The app in English and Portuguese

The platform under `/app` reads in English or Brazilian Portuguese. The site hands the language over: the Portuguese pages open `/app?lang=pt`, the English ones `/app?lang=en`. Inside the app, the EN | PT switch changes it, and the choice is remembered in the browser. Without either, the app follows the browser's language.

## How a text is written

Every sentence is written in both languages where it is used. There are no translation keys and no separate dictionary, so a change to the English text sits next to the Portuguese one it must change with.

- **Inside a component**, use `tr({ en: "…", pt: "…" })` from `src/app/i18n`. It also takes JSX: `tr({ en: <>Read <b>this</b></>, pt: <>Leia <b>isto</b></> })`.
- **In a module-level constant** (labels, tabs, navigation, reason codes), wrap the whole constant in `localized(...)` and write each text as `{ en, pt }`. The constant keeps its type: `POOL.domestic.name` is still a string, read in the current language. Never call `tr()` at module level, because it would freeze the language the module loaded in.
- **Sentences built from values** are written whole in each language, so the word order can differ: `tr({ en: \`${n} opportunities\`, pt: \`${n} oportunidades\` })`.
- **Numbers and dates** go through `formatNumber`, `formatDate`, `formatDateTime` and `formatTime` from `src/app/i18n`, never `toLocaleString("en-US")`. Reais stay in the Brazilian format (`R$ 1.234,56`) in both languages.
- **What does not change:** codes (`Q-D7CAF1`), model and consent versions, hashes, addresses, transaction ids, enum values sent to the database, and the demo data itself (names, businesses, communities, education programme titles, notes typed by people). Error keys raised by the database are translated in `src/app/lib/errors.ts`; a message the database or an edge function writes in full stays as written.
- **Stored text the app knows:** the demo's sectors (`sectorLabel` in `lib/readiness.ts`), the seeded desk's name and the note `formalise_loan` writes are read in the current language; anything else typed by a person shows as it was written.
- **The wallet's sign-in statement** stays in English: it is part of the message Supabase checks.
- **Consent:** the Portuguese wording is a translation of `consent-v2` with the same meaning; the version recorded does not depend on the language.

## Style

- **Language:** Brazilian Portuguese, in plain words for an entrepreneur who is not from finance. Use "você" and short sentences.
- **Gender:** the entrepreneur is a woman: "a empreendedora", "ela". Investors, auditors and the desk are addressed without assuming a gender where that reads naturally.
- **English terms:** keep the ones a Brazilian fintech keeps, such as P2P, Pix, USDC, devnet, hash, wallet, check-in, ticket and pool.
- **The disclaimer** in Portuguese is the one on the site's footer, word for word: "Protótipo de uma futura arquitetura regulada de crédito produtivo P2P. Investimentos, retornos, câmbio e liquidação via Pix do hackathon são simulados; as transações em blockchain usam ativos de teste na Devnet."
